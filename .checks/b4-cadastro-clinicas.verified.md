## Findings (ranked)

1. **Coverage gap, C20 (blocks PASS):** the claim excludes "atendente/**paciente** da mesma clínica". The proof seeds only an atendente (`tests/api/platform-clinic-admins.test.ts:334`) and another clinic's admin (`:335`). No patient/portal account is seeded, even though the test title says "equipe e portal" (`:327`). The code filters structurally with `findByRole('company_admin')` (`src/application/platform/manage-clinic-admins.ts:50`), so this is low risk, but the paciente member is unproven.
2. **Landing decision with no check:** "Editar não obriga cadastro completo" says `PATCH` and `PUT clinic-info` accept `null`/empty in `cnpj`/`contactPhone`/`contactEmail`. No route-level test sends `null` or `''` to either handler and asserts `200` plus `registrationComplete:false`. Only the domain covers it (`tests/domain/clinic.test.ts:239-241`), and the docs state it (ACE-RN-24). No check claims it, so no check fails.
3. **Precision, C9/C10:** "nenhuma clínica **nem conta**" is asserted only through `clinicCount()` (`tests/api/platform-clinics.test.ts:190`, `:206`). The account half holds structurally, because the account is written only inside the same `db.transaction` (`src/application/platform/create-clinic.ts:38-51`), but it is not asserted.
4. **Precision, C15 proof naming:** `-t "família negada"` selects only company_admin/atendente/profissional (`route-guard-conformance.test.ts:320`). The portal half is proven by the "rota nova nasce protegida" tests (`:211`, `:236`). They ran and passed for all 4 new routes, but the checklist's proof line would not select them.
5. **Test-name defect:** `tests/application/platform-clinic-overview.test.ts:43` - `'…Então %s'` formats the accounts array, so the reporter prints "Então [object Object],[object Object]" instead of the expected status. The assertion at `:45` is correct, but a failure would not name the expected value.
6. **Minor, C32:** the claim is "Reenviar convite só em admin pendente". The test asserts it is absent on the active row (`plataforma-clinica.test.tsx:122-124`) but not on the inactive row.
7. **Robustness note (not a check):** in `src/app/api/platform/clinics/[id]/admins/[accountId]/route.ts`, `getRepositories`, `clinics.findById` and `admins.find` run outside `handleRequest`. A DB error there escapes the `{success,error}` envelope.
